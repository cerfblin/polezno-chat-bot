## Меню в Telegram

Отправьте /start или /menu, чтобы показать кнопки. У пользователя: «Задать вопрос», «Связаться с врачом», «Статус обращения» и «Помощь». Кнопки навигации не создают запросов ИИ и не пересылаются врачу. Повторная кнопка врача показывает статус уже открытого обращения.

Врач видит «Мои обращения» и «Помощь». Список разбит на страницы по 8 обращений; кнопка выбирает собеседника. ● отмечает выбранное обращение. Ответ на конкретное сообщение по-прежнему имеет приоритет над выбором. Кнопка завершения требует подтверждения для конкретного обращения; /close сохраняет прежнее немедленное завершение. Администратору добавляются статистика и повтор доставок. Аккаунт владельца совмещает врача и администратора; обычное меню пользователя видно со второго аккаунта.

## Быстрый запуск без ключей

Требуется Node.js 24.13+; проверено на 24.19.0. Runtime-зависимостей npm нет, TypeScript исполняется встроенным Node type stripping.

    node scripts/demo.ts

Demo использует настоящую SQLite БД в памяти и транспорт, записывающий отправки без сети. Показывает полный цикл и результаты проверок.

Для разработки:

    corepack enable
    pnpm install --frozen-lockfile
    pnpm typecheck
    pnpm test

Если pnpm отсутствует, offline-demo запускается напрямую через node. Проверка TypeScript требует установки dev dependencies; runtime и node --test их не требуют.

## Подключение Telegram

1. Создайте своего бота через официальный @BotFather и получите токен.
2. Создайте закрытую рабочую группу, добавьте бота и разрешите отправку сообщений. Группа получает только карточки очереди, без медицинских файлов и истории.
3. Запишите ID группы, Telegram IDs врачей и администраторов в .env. Не публикуйте этот файл.
4. Скопируйте .env.example в .env и задайте MODE=live. Обязательные поля: TELEGRAM_BOT_TOKEN, DOCTOR_GROUP_ID (отрицательное число), DOCTOR_IDS и ADMIN_IDS (списки чисел через запятую).
5. Каждый врач должен открыть личный чат бота и отправить /start. Без этого он не сможет принять обращение.
6. При наличии webhook удалите его явно в Telegram API: сервис не меняет существующую конфигурацию webhook автоматически.
7. Запустите node --env-file-if-exists=.env src/main.ts или pnpm start.
8. Проверьте реальный цикл двумя тестовыми аккаунтами, включая фото/PDF и блокировку бота врачом.

Транспорт: long polling. Не запускайте несколько копий с одним токеном. Процесс блокирует повторный запуск с тем же файлом БД; копии с разными файлами БД должны исключаться организацией развёртывания.

Права врача задаются allow-list, а кнопка приёма принимается только из настроенной группы. Закрыть или ответить может только закреплённый врач. Администратор может одновременно быть врачом, если указан в обоих списках.

## Меню Telegram

Описание профиля и меню команд настраиваются повторяемым скриптом. Сначала проверьте вывод без сети, затем примените настройки:

    pnpm setup:telegram
    pnpm setup:telegram --apply

Скрипт задаёт пользовательские команды по умолчанию, отдельные команды для личных чатов врачей/администраторов из .env и описание. После записи читает настройки обратно; verified=true означает совпадение. При изменении списков ролей повторите применение. Старые индивидуальные меню удалённых ролей удаляются отдельно через deleteMyCommands; доступ всегда проверяется текущими allow-list, независимо от меню.

## Команды

| Роль | Команды |
|---|---|
| Пользователь | /start, /help, /doctor, /status |
| Врач | /start, /help, /cases, /case <полный номер>, /close |
| Администратор | /stats, /retry |

Первый врач, принявший карточку, получает обращение. Его личный чат содержит историю и файлы. /case выбирает обращение для следующего сообщения без reply. При нескольких обращениях безопаснее отвечать через reply на сообщение нужного обращения. Неизвестный или недоступный reply отклоняется.

Статус «ответ поставлен на отправку» означает запись в outbox, а не подтверждение доставки. При постоянной ошибке увеличивается счётчик failedDeliveries и статистика администратора. /retry повторяет все неудачные отправки.

## Материалы и каталог

data/knowledge.json содержит восемь кратких справочных пересказов NIH/NCCIH, NIH Office of Dietary Supplements и ВОЗ: общая справка о добавках, питание, витамины C/D, магний, железо, омега-3 и пробиотики. Происхождение и ссылки — docs/SOURCES.md. clinicianReviewed=false: проверки специалистом заказчика не было. enabled означает доступность справки в текущей базе.

Бот не сканирует интернет во время консультации, не добавляет ответы модели в базу и не индексирует медицинские файлы пользователей.

data/catalog.json намеренно пуст. Владелец подтвердил, что магазина/Mini App пока нет: подключение отложено до их появления. Чужой ассортимент не подставляется. Когда появится каталог, используйте свою JSON выгрузку:

    pnpm import ./catalog-export.json
    pnpm import https://your-store.example/catalog.json

your-store.example — образец адреса, не подключённый магазин. Формат записи:

    {
      "id": "unique-product-id",
      "name": "Название из вашего каталога",
      "description": "Описание",
      "composition": "Состав",
      "purpose": "Назначение из карточки",
      "restrictions": "Ограничения",
      "usage": "Способ применения из карточки",
      "inStock": true,
      "url": "https://your-store.example/product",
      "updatedAt": "2026-10-11T10:00:00Z",
      "approved": true
    }

Все записи проверяются до замены файла; неверные поля/URL/дубликаты, включая совпадение ID с медицинской справкой, отклоняют импорт целиком. JSON источника ограничен 5 MB, HTTPS перенаправления не разрешены. Запущенный бот подхватывает корректный локальный каталог примерно за секунду без перезапуска. При ошибке сохраняется последняя проверенная версия в памяти.

Для периодической загрузки задайте CATALOG_SOURCE (свой JSON-файл или HTTPS JSON-выгрузка) и CATALOG_SYNC_SECONDS (по умолчанию 300, минимум 60). При пустом CATALOG_SOURCE внешних запросов к каталогу нет. Адрес и фактическую частоту обновления должен определить ответственный магазина. Изменения .env требуют перезапуска.

Перед отправкой ответа повторно проверяются карточки из использованного контекста: наличие, approved, срок актуальности, состав/ограничения/применение и ссылка. Если данные изменились, старый ответ заменяется уточнением. Защита сохраняется в outbox и действует после перезапуска; служебные данные проверки в Telegram не отправляются. Проверка относится к последней загруженной выгрузке; уже принятый Telegram запрос нельзя отозвать.

В поиске участвуют только approved=true, inStock=true и записи не старше CATALOG_MAX_AGE_DAYS. Будущие даты исключаются. Реальная актуальность наличия зависит от выгрузки; бот не выдаёт оценку наличия из памяти модели.

Поиск базовый, по словам и префиксам, до четырёх фрагментов. Для большого каталога, синонимов и сложных формулировок потребуется семантический поиск/оценка retrieval. PostgreSQL/pgvector в этой версии не подключён.

## ИИ

Без ключа работает извлечённый ответ из базы с ссылкой; неизвестный вопрос вызывает уточнение/предложение врача.

Чтобы включить внешний LLM, задайте LLM_API_KEY и LLM_MODEL одновременно, при необходимости LLM_BASE_URL. Модель и провайдер должны поддерживать Chat Completions с response_format=json_schema и max_completion_tokens. Ключ и модель не подставляются автоматически. Таймаут задаётся LLM_TIMEOUT_MS.

Приложение проверяет результат независимо от schema: действие, наличие оснований, sourceIds/productIds, посторонние ссылки и некоторые формулировки назначений/дозировок. URL добавляются только из локальной базы. Это не медицинская экспертиза текста и не гарантия отсутствия всех ошибок модели; требуется оценка на реальных сценариях перед рабочим применением.

Персональные назначения, анализы, изображения, прямой запрос и многие формулировки симптомов ведут к врачу. Во время очереди/консультации самостоятельный ответ ИИ не отправляется. Версия разговора проверяется при завершении модели и перед отправкой outbox. Уже принятый Telegram запрос нельзя атомарно отменить: узкое окно сетевой гонки не исключается.

Контекст LLM — последние 20 текстовых сообщений текущего разговора с общим бюджетом 16 000 символов; файлы в LLM не отправляются. Полная история врача не ограничена этим бюджетом. AI_RATE_PER_MINUTE ограничивает новые запросы ИИ; доступ к врачу и файлы врачебного диалога этим лимитом не блокируются.

## Источники и график

Ссылка вида https://t.me/YOUR_BOT?start=partner_label фиксирует разрешённый Telegram payload. YOUR_BOT нужно заменить именем вашего бота. Допустимы 1–64 символа A–Z/a–z/0–9/_/-. First-touch пользователя сохраняется, latest-touch меняется при новом валидном переходе; источник обращения фиксируется при создании разговора.

Метки не подписаны и не являются доказательством личности партнёра. Статистика показывает метку перехода, а не верифицированную коммерческую атрибуцию.

TIMEZONE по умолчанию Europe/Moscow. WORK_SCHEDULE — JSON, где 1=понедельник, 7=воскресенье, интервалы HH:MM. Ночные интервалы поддерживаются. Пустой график обозначается как «не настроен»; срок ожидания не выдумывается.

    WORK_SCHEDULE={"1":[["09:00","18:00"]],"2":[["09:00","18:00"]]}

Это пример конфигурации, не установленный график врачей.

## Данные и анонимность

SQLite WAL хранит историю, состояние, Telegram routing IDs, file_ids, журнал обновлений и исходящие задания. Логи runtime не содержат токенов, Telegram ID и текстов консультаций. Обработанный inbox очищает raw payload. Аудит хранит переходы и ID врача, без текстов.

Врачу не передаются профиль/имя из Telegram, username, Telegram ID пользователя и forward-origin. Используются новые send* запросы по file_id, не forwardMessage. Явные телефоны/email/Telegram-контакты в текстах/captions маскируются.

Это не полное обезличивание: ФИО, контакты и другие сведения внутри изображения/PDF/аудио, имён файлов или свободного текста могут сохраниться. OCR/редактирование бинарных файлов не реализованы; интерфейс предупреждает пользователя перед отправкой файлов. Файлы доступны через Telegram file_id, независимая архивная копия не создаётся.

Удаление старых данных и срок хранения не настроены, поскольку требования не определены. Администратор обязан ограничить доступ к диску/backup и определить срок хранения перед рабочим запуском.

## Надёжность и обслуживание

Incoming update сохраняется до продвижения offset. Изменение состояния, история и outbox фиксируются в транзакции. Необработанные обновления повторяются; update_id исключает повтор побочных действий. При перезапуске running AI jobs возвращаются в очередь и повторно проверяют состояние.

429 учитывает retry_after; сеть/5xx повторяются с backoff. После восьми неудачных попыток доставка отмечается failed. Очередь доставки сохраняет порядок для каждого чата; другие чаты могут продолжать работу. Постоянные 4xx, кроме 429, сразу failed.

Доставка имеет семантику at-least-once: авария после принятия Telegram и до записи успеха может привести к дублю. Нельзя гарантировать exactly-once доставку Telegram sendMessage.

Health endpoints доступны только на 127.0.0.1:PORT:
- GET /health — процесс работает, число failed доставок.
- GET /ready — Telegram polling подключён.
- Другие пути возвращают 404, истории/ID/секреты наружу не выдаются.

SIGINT/SIGTERM останавливают polling, завершают текущий рабочий цикл, закрывают сервер/БД и снимают lock. После аварии lock с несуществующим PID снимается при новом запуске; активный PID не вытесняется.

Backup с согласованным SQLite snapshot:

    node --env-file-if-exists=.env scripts/backup.ts ./backups/polezno.sqlite

Восстановление: остановить сервис, сохранить текущую БД отдельно, заменить основной файл проверенным snapshot, убрать старые файлы -wal/-shm только при остановленном процессе, запустить и проверить /ready и обращения. Не копируйте один sqlite файл работающего WAL-процесса вместо snapshot.

Docker:

    docker compose up -d --build

Dockerfile работает без npm install, от пользователя node, хранит var в volume. Docker отсутствовал в среде разработки: сборка/запуск контейнера не проверялись. HTTP healthcheck выполняется внутри контейнера, порт не публикуется.

## Повторяемая приёмка ИИ

    pnpm evaluate --output docs/evaluation-offline.json
    pnpm evaluate --live --output docs/evaluation-live.json

Без --live используется справочный ответчик без сети. --live выполняет четыре запроса к выбранному внешнему ИИ на синтетических вопросах; Telegram API и производственная БД не используются. Семь сценариев проверяют общую справку, уточнение в контексте, магний, неизвестный товар, персональный приём и паузу ИИ, медицинский файл, вопросы заказа. Проверяются маршрутизация, история, IDs источников и доставленные ссылки. Это не клиническая экспертиза текста модели. Подробности: docs/VERIFICATION.md.

При ошибке доставки истории или ответа последующие сообщения того же обращения удерживаются до успешного административного /retry. Другие обращения и общие служебные команды продолжают работать. Перед /retry устраните причину отказа Telegram (например, блокировку бота). Уже успешно отправленные вложения повторно не ставятся на отправку.

## Ограниченная offline-проверка очереди

    pnpm check:load --output docs/load-check.json

Команда не загружает .env, не открывает рабочую БД и не вызывает Telegram/ИИ. Проверяет 100 синтетических обращений на фоне 10 000 старых отправок, 200 вложений, ошибки 429/403, перезапуск, административный /retry и повторы входящих обновлений. Временная SQLite удаляется после завершения; аварийное принудительное завершение может оставить тестовую папку. Локальное время прогона не оценивает скорость внешних API. Текущий отчёт — docs/load-check.json; применение новой версии к рабочему процессу отслеживается отдельно в docs/verification-results.json.

## Проверка настроек и подключение ответственных

    pnpm check:readiness --output docs/configuration-readiness.json

Команда читает настройки и метаданные материалов/каталога, без переписки, Telegram/LLM-запросов и значений ключей/ID. Она показывает наличие каталога, отметок проверки справок, врачей и графика; не подтверждает квалификацию человека или медицинскую готовность. Пакет для ответственного специалиста — docs/MEDICAL-REVIEW.md.

Для реального врача владелец добавляет согласованный Telegram ID в приватный DOCTOR_IDS, при необходимости ADMIN_IDS; затем врач открывает бота, отправляет /start и принимает тестовое обращение. Настоящие часы записываются в WORK_SCHEDULE по существующему формату; примеры расписаний не считаются фактическим графиком. Изменения окружения требуют перезапуска.

Примеры размеченных ссылок для будущей выдачи (метки тестовые, реальные партнёры не назначены): https://t.me/polezno_consultant_bot?start=doctor_test и https://t.me/polezno_consultant_bot?start=partner_test. Проверять со второго пользовательского аккаунта: основной аккаунт сейчас имеет роль врача. /stats показывает первый/последний источник и принятия/закрытия по врачам. Ссылку будущего Mini App настроить после его появления.

## Прямые ответы внешнего ИИ

По решению владельца 12.10.2026 рабочая настройка `LLM_ANSWER_MODE=direct` разрешает модели отвечать на общие вопросы по собственным знаниям даже без локальной справки. Память текущего диалога сохраняется, подходящие справки используются как дополнительный контекст. Это не поиск в живом интернете и не клиническая проверка. Ссылки добавляются только для использованных записей, IDs проверяются; товары Polezno по-прежнему описываются только по реальному каталогу. Назначения, персональные медицинские вопросы и файлы передаются врачу.

`LLM_ANSWER_MODE=sources` возвращает прежнее ограничение материалами; отсутствие настройки по умолчанию сохраняет sources для совместимости. Прямому live-режиму нужен внешний API-ключ. Проверка `pnpm check:llm --live` в режиме direct выполняет один синтетический запрос без evidence/истории пациентов. Настройки окружения применяются после перезапуска.

Для единого ПРИВАТНОГО ZIP по последнему решению владельца добавить `-IncludeKey` в Build-Package.ps1. Ключ восстановления уже внутри; такой архив не защищён от того, кто его получит. START-HERE.md содержит все команды с правильными путями. Внутри есть текущие токены Telegram/OpenRouter, роли, график/параметры окружения и история SQLite в восстанавливаемом зашифрованном блоке. Аккаунт Codex и общий runtime не переносятся.
