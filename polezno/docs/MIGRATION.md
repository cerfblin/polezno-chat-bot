# Инструкция переноса Polezno

12.10.2026 владелец поручил подготовить актуальный комплект для другого ПК. Бот продолжает временно работать на исходном компьютере, постоянный автозапуск выключен. Предварительный пакет позволяет проверить восстановление, но не учитывает сообщения после времени snapshot. Перед включением нового экземпляра остановить исходный и собрать финальный пакет: только один polling-процесс с токеном. Старым snapshot не заменять текущую рабочую БД.

Главная инструкция находится в START-HERE.md в корне комплекта; TRANSFER-STATE.json фиксирует время, состояние источника и предварительность копии. Исходное ТЗ сохранено в docs/SPEC-ORIGINAL.md, контекст — в docs/CHAT-HANDOFF.md, проектный скилл — в .agents/skills/polezno-continue/SKILL.md. Учётная запись Codex для исполнения бота не переносится.

## Сборка актуального комплекта

В исходном проекте после остановки бота:

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/transfer/Build-Package.ps1 -ProjectPath . -OutputPath "ПУТЬ/polezno-transfer-final" -NodePath "ПУТЬ/node.exe"

Без -LiveSnapshot сборщик откажет при активном lock исходного процесса. Он не останавливает и не запускает бот. Для предварительной копии работающего источника явно добавить -LiveSnapshot. Выбирать новый OutputPath: существующие папка, ZIP и ключ не перезаписываются. Для каждой сборки создаётся новый отдельный ключ; переносить ключ именно от нужного архива. Проверка snapshot включает целостность, foreign keys и схему SQLite. Внутренние пути .env автоматически приводятся к стандартным относительным путям нового проекта.

## Состав пакета

- polezno/ — актуальный проект, AGENTS.md и .agents/skills/polezno-continue/SKILL.md.
- private/polezno-private.pzenc — зашифрованные настройки и snapshot истории.
- restore-private.mjs — автономная распаковка на Node.js без npm-зависимостей и сети.
- SHA256SUMS.json — контрольные суммы открытых файлов и зашифрованной части.
- START-HERE.md — краткие шаги и готовое сообщение новому Codex.

Файл <имя-пакета>-key.txt находится отдельно от архива; точное имя указано в START-HERE.md. Передать его приватно. Не вставлять ключ, .env или историю в чат. В зашифрованной части AES-256-GCM; ключ выводится из случайного секретного значения через scrypt. Это перенос данных владельца, не публичный архив для публикации.

## На новом компьютере

1. Распаковать ZIP в постоянную папку. Сохранить отдельный файл ключа локально с ограниченным доступом.
2. Установить самостоятельный Node.js 24.13+ и проверить node --version. Не использовать старый путь .cache/codex-runtimes. Боту не требуется запущенное окно Codex для исполнения Node.js-процесса.
3. Из корня распакованного пакета сначала проверить приватный блок без записи файлов:

       node restore-private.mjs --package private/polezno-private.pzenc --key-file "ПУТЬ-К-КЛЮЧУ/polezno-transfer-key.txt" --verify

4. Расшифровать в новую, ещё не существующую папку; существующая папка не перезаписывается:

       node restore-private.mjs --package private/polezno-private.pzenc --key-file "ПУТЬ-К-КЛЮЧУ/polezno-transfer-key.txt" --out private-restored

5. Приватно скопировать private-restored/.env в polezno/.env. В новой пустой polezno/var положить private-restored/polezno.sqlite как polezno/var/polezno.sqlite. Если там уже есть файлы, сначала проверить их и сохранить отдельно. Не копировать старые lock.pid, -wal/-shm и node_modules.
6. Проверить пути в .env. Для стандартной установки DATABASE_PATH=var/polezno.sqlite. Сохранить действующие Telegram IDs и бесплатные настройки OpenRouter; MINI_APP_URL оставить пустым. Не показывать значения токенов в выводе.
7. Открыть polezno как проект в новом Codex, в другом аккаунте. Прочитать AGENTS.md, вызвать $polezno-continue или прямо указать путь .agents/skills/polezno-continue/SKILL.md. Скилл уже размещён в проекте; глобальная установка на старом ПК не нужна. Если версия приложения не обнаруживает его, открыть SKILL.md вручную и попросить использовать его. Формат и расположение сверены с [официальной документацией OpenAI](https://learn.chatgpt.com/docs/build-skills).

## Проверки перед включением

В папке polezno:

    node scripts/demo.ts
    node --test tests/*.test.ts

Эти команды без внешней сети и без производственной истории. Тест runtime использует отдельную синтетическую БД и имитацию Telegram, не рабочий токен. Последняя проверка кода — 84/84; typecheck passed. Для typecheck установить dev dependencies по pnpm-lock.yaml и выполнить pnpm typecheck. Не устанавливать и не скачивать локальные модели.

На выбранном новом ПК после настройки .env:

    node --env-file=.env scripts/check-llm.ts --live
    node --env-file=.env src/main.ts

Первая команда — один синтетический запрос к внешней модели, не Telegram и не история пациентов. Вторая запускает живой polling, поэтому сначала убедиться, что старый экземпляр выключен. Проверить /ready, общий вопрос и уточнение, затем двумя аккаунтами очередь врача/ответ/закрытие. При пустой новой БД врачам потребуется заново /start; при сохранённом snapshot регистрация уже перенесена.

Если бесплатный маршрут недоступен, не включать платные модели и не ослаблять фильтры данных. Текущий ключ OpenRouter был создан до 09.01.2027, его актуальность/квоты проверяются на новом ПК. Для подготовки этого пакета внешние Telegram/LLM API не вызывались.
