# Polezno — всё для переноса в одном ЧАСТНОМ архиве

Подготовлено 12.10.2026, Europe/Moscow. ПРЕДВАРИТЕЛЬНАЯ КОПИЯ: исходный бот продолжает работать. Перед боевым запуском нужен финальный пакет после его остановки.
Точное время и состав snapshot — TRANSFER-STATE.json. Бот работает отдельным Node.js-процессом; открытое окно Codex для него не требуется.

## Что перенести

1. ZIP этого пакета: актуальный проект, исходное ТЗ, workflow, отчёты, скилл и зашифрованные настройки/база.
Ключ уже включён: **private/restore-key.txt**. Отдельно ничего переносить не нужно. Этот ZIP даёт доступ к токенам Telegram/OpenRouter и приватной базе; не публиковать, не загружать в публичные репозитории и не вставлять содержимое ключей в чат. Шифрование внутреннего блока не защищает от владельца ZIP: ключ находится рядом.

В архив не входят открытая .env, SQLite/WAL/lock, node_modules, старые backup/логи, кеш Codex, аккаунт Codex, скриншоты ключей ; ключ расшифрования по прямой просьбе владельца включён внутрь. История в зашифрованной базе приватна. Исходники содержат 90 теста; последние результаты — 90/90 и strict typecheck, подтверждение ИИ и фото/PDF от владельца. Это прежние результаты, не гарантия доступности провайдера на новом ПК.

## Подготовка нового компьютера

1. Распаковать ZIP в постоянную папку. Установить самостоятельный Node.js 24.13+; проверить `node --version`. Пути кеша старого Codex не переносить.
2. В корне пакета выполнить `node verify-package.mjs`.
3. Проверить приватную часть без записи:

       node restore-private.mjs --package private/polezno-private.pzenc --key-file "private/restore-key.txt" --verify

4. Расшифровать в НОВУЮ папку:

       node restore-private.mjs --package private/polezno-private.pzenc --key-file "private/restore-key.txt" --out private-restored

5. Перенести private-restored/.env в polezno/.env, private-restored/polezno.sqlite — в новую polezno/var/polezno.sqlite. Существующие файлы сначала сохранить и проверить, не перезаписывать вслепую. DATABASE_PATH/KNOWLEDGE_PATH/CATALOG_PATH уже приведены к относительным путям. Содержимое секретов и переписки не выводить.
6. Открыть `polezno` в другом аккаунте Codex. Проектный скилл находится в `.agents/skills/polezno-continue/SKILL.md`; глобальная установка не нужна. Если скилл не обнаружен автоматически, поручить прочитать файл по этому пути.
7. В polezno выполнить `node scripts/demo.ts`, `node --test tests/*.test.ts`. Эти проверки используют синтетические данные и имитации API. Для typecheck нужны только dev dependencies: `corepack pnpm install --frozen-lockfile`, затем `corepack pnpm typecheck`; при недоступном Corepack использовать установленный pnpm. Runtime npm-зависимостей нет.

## Обязательный финальный переход

Предварительный snapshot фиксирует момент подготовки. Пока старый бот работает, в нём могут появиться новые сообщения. Такой snapshot нельзя считать финальной базой для запуска.

На исходном ПК поручить Codex: дождаться пустых очередей по агрегатным счётчикам, сохранить проверенную копию, остановить ТОЛЬКО подтверждённый процесс этого проекта и убедиться, что он не запустится снова. Автозапуск здесь сейчас отсутствует. Затем пересобрать новый пакет командой из корня ИСХОДНОГО проекта (NodePath — локальный node.exe, OutputPath — новая папка вне проекта):

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/transfer/Build-Package.ps1 -ProjectPath . -OutputPath "ПУТЬ/polezno-transfer-final" -NodePath "ПУТЬ/node.exe" -IncludeKey

Без `-LiveSnapshot` сборщик откажет при активном локальном lock. Он сам не останавливает и не запускает бот. Каждый пакет имеет отдельный новый ключ. Финальный единый ZIP с внутренним ключом перенести на новый ПК, восстановить в новую папку, проверить TRANSFER-STATE.json: `preliminary=false`. Не использовать ключ предварительного пакета для финального.

После подтверждения остановки старого экземпляра и восстановления финального snapshot на новом ПК:

    node --env-file=.env scripts/check-llm.ts --live
    node --env-file=.env src/main.ts

Первый вызов — один технический запрос без истории пациентов. Второй включает Telegram polling; одновременно допускается один экземпляр с этим токеном. Проверить http://127.0.0.1:3080/ready и цикл общий вопрос → уточнение → врач → ответ → закрытие → новый разговор. Аккаунт владельца — врач/администратор; обычное меню и ИИ проверяются со второго аккаунта. Консультация queued/doctor приостанавливает ИИ. При сохранённой базе обращения, выбранные врачами диалоги и /start-регистрация сохраняются.

## Сообщение новому Codex

> Продолжи существующий проект Polezno по скиллу .agents/skills/polezno-continue/SKILL.md. Сначала прочитай START-HERE.md, TRANSFER-STATE.json, polezno/AGENTS.md, docs/CHAT-HANDOFF.md, docs/MIGRATION.md и docs/SPEC-ORIGINAL.md. Не начинай с нуля и не восстанавливай старый snapshot поверх новой рабочей базы. Настройки и история зашифрованы, ключ включён в private/restore-key.txt по прямому решению владельца. Архив целиком приватный; восстанови локально, не печатай секреты/переписку. Если пакет предварительный, подготовь новый ПК offline, но не запускай polling до остановки старого бота и получения финального snapshot. Сохрани LLM_ANSWER_MODE=direct по последнему решению владельца: общие вопросы идут в модель без обязательной локальной справки, с памятью текущего диалога; источники необязательны, персональные медицинские вопросы и файлы — врачу. Это не живой интернет-поиск и не медицинское одобрение. Сохрани внешний бесплатный Apodex/OpenRouter, нулевые max_price, ZDR и запрет сбора данных; Codex не является ответчиком, локальную модель не устанавливать. Каталога/Mini App ещё нет, 8 справок не одобрены врачом, владелец — тестовый врач; не выдумывай реальные данные. Выполни необходимые проверки и продолжи оставшиеся пункты по WORKFLOW §24. Текущий ПК использовался временно; после проверенного переноса удалить с него только файлы/данные/ключи/архивы Polezno по согласованному условию. До проверки нового места ничего из единственных исходных данных не удалять. Доступ к старому ПК или аккаунту Codex не извлекай. Новые расходы, рассылки и постоянный автозапуск без соответствующего решения владельца не включать.

Технические автотесты не заменяют медицинское одобрение. Содержимое и имена файлов не обезличиваются автоматически. Docker/полный автоперезапуск планировщиком ещё не подтверждены; на новом ПК не заявлять их проверенными заранее.

## Очистка старого ПК после приёмки

Владелец потребовал убрать бот после переноса. Только после проверки нового единственного экземпляра и сохранности базы удалить исходный проект, .env, DB/backup/логи, staging/ZIP всех версий переноса, отдельные ключи, относящийся к Polezno скриншот ключа и временные файлы проекта. Перед удалением проверить абсолютные пути. Общий runtime, другие проекты и аккаунт Codex не трогать; текущий пакет и ключ сохранять до успешного восстановления.
